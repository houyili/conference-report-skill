一页结论

端到端测试成功，暴露的问题集中在“报告写作质量定义”上。

符合预期

工程链路跑通

安装版 CLI、登录态、fast profile、agent gate、repair gate、final validation 都完成。

不符合预期

报告读感机械

正文出现 evidence.json、slide_index 等审计脚手架。

根因

验证压力泄漏到 prose

writer 为了证明有证据，把本该留在 grounding 的信息写进正文。

这条链路说明 agent-native 编排可以工作，问题不在“能不能完成”。

好与坏

左边证明架构方向正确，右边说明下一轮要改质量门槛。

符合预期

  • 没有退回开发目录或 python -m 路径。
  • 已安装 skill 能解析 CLI 并完成 use-stage run。
  • subagent provenance 满足单报告隔离要求。
  • report-quality repair gate 能产生实际修复价值。

不符合预期

  • validator 通过，但人读起来仍像执行日志。
  • coverage 规则倒逼 第 N 张 这种标题格式。
  • 低信息页、重复 Q&A 页仍可能进入主报告。
  • grounding review 没有主动标出 prose style 问题。

抽样审计新增发现

已抽查 20 个 slide section，对照 evidence、cognition、report、grounding，并手动看了 4 张疑点截图。

内容层

大体 grounded

抽样页中，cognition 与 report 的核心 claim 通常一致，问题不是大规模幻觉。

正文层

审计脚手架外露

4 份报告分别出现 41 / 22 / 92 / 45 个 slide_index 或 evidence marker。

Review 层

style issues 全部漏报

4 个 grounding JSON 的 template_or_style_issues 都是空数组。

Identity

slide 编号被混用

本地 evidence 序号、原始 PPT slide_index、报告页序号不是一回事。

边界页

跨 talk / 过渡页进入正文

Hubble 的第 1 个主报告 section 实际还是上一场 LLM DNA 结束页。

中间层

缺少 synthesis 承接

cognition 有好信息，但没有沉淀成整场 talk 的论证地图。

为什么会刻板

不是 writer 完全没理解，而是系统奖励了“逐页可验收”。

Prompt 偏局部

要求每页对齐 PPT + ASR，但没有强制先做整场 talk 的 argument map。

Validator 偏结构

能抓缺页、复制、没用 QA，却不会判断“这页如何推进论文”。

证据锚点外露

支撑信息应该在 grounding JSON 里，而不是变成正文第一句话。

系统编排改进视角

这轮不只改文风，还要改 subagent 何时启动、如何接收反馈、哪些理解要沉淀。

Prompt 与时机

report writer 先综合，后成稿

writer 启动前必须等 cognition/QA 依赖验证通过；启动后先形成 talk-level synthesis，再写最终报告。

硬编排

CLI 控制顺序，manifest 控制边界

父 agent 只协调；是否 ready、能写哪里、下一步做什么，都由 pipeline_state 与 task manifest 决定。

反馈闭环

失败原因要可执行

质量反馈拆成 support、coverage、style、scaffolding、synthesis，不只给一句“没过”。

中间沉淀

新增理解层 artifact

talk_synthesis.md 记录整场理解、slide role map、Q&A 边界，让理解可审计但不污染正文。

改进优先级

P0 先让报告好写、validator 不误导；P1/P2 再完善体验和状态。

P0

改 writer contract

先建立整体理解，再写逐页解释；禁止审计语言进入正文。

P0

放宽 coverage parser

同时接受 第 N 张、Slide N、slide_index: N。

P0

拆清 slide identity

区分本地 evidence 序号、原始 PPT 编号和报告展示序号。

P0

依赖验证后再 dispatch

report writer 不能只因文件存在就启动；cognition/QA 必须先过 gate。

P1

区分主报告与证据页

低信息页和重复页保留可追溯性，但不强迫写成长段解读。

P1

新增 style-quality gate

检测重复开头、显式证据脚手架、模板化段落。

P2

增加 talk synthesis

新增 talk_synthesis.md 或 argument_map.json。

P2

修复 repair 状态表达

final OK 后把历史 repair plan 标成 resolved 或 superseded。

怎么改

三块核心代码方向，加一组针对性测试。

conference_report/report.py

调整 writer prompt、report task quality contract、grounding review instructions。

证据页处理

覆盖 dispatch readiness、反馈分类、中间 synthesis、标题格式和 style issues。
